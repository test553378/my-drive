# ぼくの GRAND RACE

4〜5歳向けの、オリジナル車両で走る3Dレースゲームです。WebGL 1で描画し、GitHub Pagesに静的ファイルとして配置できます。実行時の外部ライブラリ・外部ホストへの通信・広告・課金・アナリティクス・個人情報の入力や送信はありません。

## Ver.4 の変更

- **初期化失敗の原因を再現して修正**：共有uniform `uEye` の頂点側 `highp` / フラグメント側 `mediump` の不一致でプログラムのリンクが失敗していました。変更前のHEADをChromiumとWebKitの両方で再現しています。詳細は[調査・検証報告](docs/VERIFICATION.md)を参照してください。
- フラグメント側の重複uniformをなくし、カメラ相対座標から視線を計算。varyingの精度も両側で明示。フラグメントの高精度浮動小数点は必須にしていません。
- 見えるコース区間だけを描画し、描画ピクセル数を画面の縦横・GPU上限に合わせて制限。初期110万ピクセル以下、遅い状態が続くと自動で段階的に48万ピクセルまで下げます。MSAAは無効です。
- WebGLコンテキスト喪失時には描画とレースを停止し、復帰イベントでシェーダーとGPUバッファを再構築。再開にはタップが必要です。復帰しない場合の再読み込みと軽い画質の選択肢も用意しました。
- オリジナルのスーパー系 **NOVA R** とスポーツ系 **AERO S**、各4色。立体フェンダー、ボンネット、ガラス、ライト、リムを描画し、前輪の向き・距離に連動するタイヤ回転・加減速時のピッチ・旋回時のロールを追加・調整しました。
- 自動アクセル・自動コース追従・ボタンを離すと中央へ戻る補助・コース端のガード。ターボなし、操作なしでも2周を完走できます。接触は軽い減速で、失格はありません。
- 大きな「ひだり」「みぎ」ボタン。指のキャンセル・ウィンドウ離脱・バックグラウンド移行で押下状態を解除します。カウントダウン中も一時停止できます。
- 最初はミュート。音声はオンにした際だけ初期化し、音声を利用できなくてもレースは動作します。OSの「視差効果を減らす」に相当する設定で車体の揺れと画角変化を抑えます。
- 初期化段階、シェーダーログ、WebGLの状態、描画サイズ、走行状態を端末内の診断画面で確認できます。自動保存・自動送信はなく、コピー／JSON保存は利用者の操作時だけ行います。

グランツーリスモのような落ち着いた追従カメラや車体表現を参考にした軽量な独自実装です。実在の車種・ロゴ・ゲーム素材は使用していません。家庭用ゲーム機相当の写実表現ではありません。**iPad実機での安定性・画質・フレームレートは未検証です。**

## あそびかた

1. 車の形と色を選び「レース スタート！」をタップ。
2. アクセルと道に沿った走行は自動。◀／▶を押す間だけ左右へ移動します。
3. 手を離すとゆっくり中央へ戻ります。両方を同時に押すと中央復帰が働きます。
4. ⚡ターボはお好みで。ゲージが回復すると再び使えます。
5. Ⅱで一時停止、▶で再開。PCは左右キー・スペース（ターボ）・Escape（一時停止）に対応します。

## 動作診断

右上の「？」、またはエラー画面の「おとなのかたへ：動作診断」を開きます。開いた際はレースが一時停止します。

- `context-unavailable`：WebGLコンテキストが取得できなかった。GPU・iPadOS・Safariのどれが原因かはこの情報だけでは断定できません。
- `shader-compile-failed` / `program-link-failed`：対象シェーダーと実際のコンパイラー／リンカーログを記録します。
- `render-failed`：描画中の例外やWebGLエラーを検出しました。
- `context-lost` / `context-restored`：喪失とGPUリソース再構築を記録します。
- `asset-load-failed`：ローカルのスクリプトやCSSを読み込めませんでした。

報告する場合はJSONに**iPadの機種、iPadOSのバージョン、Safari／ホーム画面起動の別、発生操作**を手動で添えてください。端末識別子・UA・Cookie・位置情報は収集していません。軽い画質はURL末尾に `?quality=low` を付けても選べます。

## GitHub Pages

現在の設定（`main` ブランチ、`/(root)`）で利用できます。PRをマージした後、Pagesのビルド完了を確認して開いてください。

公開URL：<https://test553378.github.io/my-drive/>

配置する実行ファイル：

```text
index.html
style.css
diagnostics.js
game.js
driving.js
service-worker.js
manifest.webmanifest
icon.svg
.nojekyll
```

ビルド・サーバー・APIキーは不要です。JavaScriptモジュールを使うため、`file://` での直接起動には対応しません。パスはすべて相対指定で、`/my-drive/` のようなサブディレクトリでも動作します。

初回のオンライン読み込みで必要ファイルをまとめてキャッシュします。2回目以降はオフライン起動に対応しますが、Safariが保存データを削除・退避した場合は再びオンライン読み込みが必要です。初回オフライン起動はできません。Ver.4のキャッシュはアプリ一式を同じ版から供給し、更新時にこのゲームの古いキャッシュだけを削除します。アプリ更新時は `service-worker.js` の `CACHE_NAME` も更新してください。

更新後に古い版が残る場合はオンラインで再読み込みし、一度ページ／ホーム画面アプリを閉じて開き直します。診断レポートの `version` が `4.0.0` であることを確認してください。

## 開発・自動テスト

Node.js 22以上を使用します。npm依存は開発・テスト専用で、ゲーム本体から読み込みません。

```sh
npm ci
npm run check
npm test
npx playwright install --with-deps chromium webkit
npm run test:e2e
```

手動のローカル確認：

```sh
node tests/serve.js
# http://127.0.0.1:8765/my-drive/ を開く
```

`npm test` は完走・操作補助・接触・ターボ・時間刻みを検証します。`npm run test:e2e` はChromiumとWebKitで実シェーダーと描画、操作、縦横画面、診断、障害の注入、コンテキスト復帰、オフライン起動を検証します。GitHub Actionsにも同じチェックを追加しています。

Linux上のWebKitとiPadプロファイルは、実際のiPad Safari／Metal GPUの代替にはなりません。[検証報告と実機チェック項目](docs/VERIFICATION.md)を参照してください。
