# Ver.4.2 Phase 2 — 1車両・1コースの画質試作

## 確認用ページ

公開先：<https://test553378.github.io/my-drive/graphics-lab/>

「車をみる」で指による回転・ピンチ、「前」「後」で視点切替、「走ってみる」でC01の閉じた3Dコースを自動前進できます。左右とブレーキで位置を変え、景色・反射・車輪・接地を確認してください。上部の高画質／標準／軽量は実際の解像度・モデル・影の品質を変更します。「i」でFPS・読込量・診断JSON、自動調整の設定を確認できます。

このページは映像を評価する試作です。既存ゲームはWebGL 1のVer.6を維持し、全車両・コース・パンク等の機能を削除していません。通常ゲームの操舵・中央復帰とAIはまだ改修していません。試作だけの操舵は画質を確認しやすいよう横位置を保持します。主ゲームへのFR-07反映はPhase 3、AIはPhase 4、全車種への展開はPhase 5です。今回のユーザー指示に従い、画質評価の前に全体移行はしません。

## 採用した実装

- Three.js **0.187.0** / WebGLRenderer（WebGL 2）、GLTFLoader、MeshoptDecoder、HDRLoader、OrbitControls。固定版を1本のJavaScriptへバンドルして自己ホスト。WebGPU・実行時CDN・外部ライブラリ配信を使いません。
- 外部制作の **Car Concept** GLB。元モデル約21.3万三角形。高画質は21万3,195、標準／軽量は10万756三角形。ソースの4輪階層を維持し、操舵・距離に連動する車輪の回転、車体のロール／ピッチを実装しました。実在メーカー車ではありません。
- 実写由来の **Asphalt Track** の色・OpenGL法線・粗さを、実寸約2mのUVスケールで道路の3D形状に貼っています。3D縁石・ガードレール・支柱・ピット・観客席、線・薄いタイヤ痕、地面を配置。既存C01の1400mの曲線を共有し、カメラは実空間で移動します。
- **Zwartkops Curve Sunset** の1K HDRを背景・環境反射・PBR照明へ利用。照明用にPMREMを生成し、金属塗装・クリアコート・ガラス・ホイールに反映。撮影画像は遠景、近くの道路や建物は3Dです。
- 実際の方向光シャドウマップを車体・車輪から路面へ投影。ガラスは透明度＋環境反射で表現し、画面全体を再描画する屈折パスは避けました。ポストプロセスの強いぼかし・モーションブラー・ブルームは使いません。
- 同じ材質で動かない車体部品を統合し、静的な箱状部品はインスタンス化。見た目と4輪の可動階層を維持して描画回数を削減。画質切替時は旧モデルのGPUリソースを破棄します。
- WebGL生成拒否、モデル／画像のファイル名・HTTPエラー、シェーダーログ、喪失・復帰を診断します。GPU喪失中に古いGPU資源を解放し、復帰時にはCPU側に保持したモデル・画像・HDRからGPU資源と照明を再生成し、利用者のタップで再開します。診断・計測は端末内だけで扱い、保存は利用者の操作時のみです。

## 配信量と画質設定

1Kの路面3マップ計約2.15MB、HDR約1.55MB。Meshopt圧縮したGLBは高画質約5.25MB、モバイル版約4.20MB。JavaScriptバンドルは約0.70MBです。初回ファイル実体の合計は標準／軽量で約8.6MB、高画質で約9.7MB。20MB以下の目標内です。これは素材・ページ等の実ファイルサイズを合算した値で、HTTPヘッダーやキャッシュ状態・圧縮率を含む通信料金の計算ではありません。

| 設定 | 描画ピクセル上限 | 影 | 車両三角形数 |
|---|---:|---:|---:|
| 高画質 | 145万 | 2048² | 213,195 |
| 標準（初期） | 95万 | 1024² | 100,756 |
| 軽量 | 48万 | 512² | 100,756 |

初回の描画量は、標準・軽量が約24.5万三角形／102描画、高画質が約47.6万三角形／102描画でした（影のパスを含む、Linux WebKitの近接ビュー）。GPU資源数の初回スナップショットは54ジオメトリー・19テクスチャです。[描画量記録](../graphics-lab/comparison/render-cost.json)。この上限管理・軽量モデル・単一光源をiPadでの性能確保の初期構成とし、実機が30〜60fpsを達成するとはまだ判定しません。

表示が遅い状態が続く場合は段階的に画質を下げます。「i」から自動調整を解除して同じ画質を維持できます。見えるピクセル上限は縦横・GPU上限も考慮します。fps表示は可視フレームの間隔による実測で、GPU処理時間やiPadの性能予測ではありません。

## 自動検証と未検証範囲

単体テストは既存35件＋新規5件。モデル階層とロゴ除去、サイズ／ハッシュ、実際の道路の法線とPBRマップ、横縦解像度上限、遅いフレームの計測、部品統合の位置保持を検証します。ブラウザーテストは実シェーダー・描画ピクセル・モデル読込・3D走行・左右操作・車輪・ブレーキ・画質切替とリソース解放・失敗注入・照明を含むGPU復旧を対象とします。最終結果はこの変更のGitHub ActionsとPRに記録します。開発中の強制GPU復帰テストで、古いコンテキストの反射バッファを復帰後に解放すると `INVALID_OPERATION (1282)` が起き、反射が暗くなる不具合を確認しました。GPU喪失中の解放と復帰後の再構築に修正し、2回連続の喪失・復帰でも実際の描画ピクセルとエラー値を確認します。

iPad第9世代の実機は利用できません。**30fps最低目標／60fps目標の達成、実際の初回読込時間、発熱・バッテリー・メモリ圧迫、Mobile Safariの多点タッチ・連続タップ、縦横回転・ホーム画面起動とGPU復帰は未検証です。** Linux上のWebKitやChromiumをiPad実機の検証と扱いません。試作は初回オンライン読込が必要で、オフライン配信は評価後の統合時に検討します。既存ゲームのオフライン対応は維持します。

## iPadで確認する順序

1. 横向きのSafariで試作URLを開き、まず標準画質で車を回転・拡大する。曲面・ガラス・リム・タイヤ・路面・接地影が期待に近いかを確認する。
2. 高画質に切り替え、必要なら「i」の自動調整を解除して比較する。FPSが低い・操作が遅い場合は標準／軽量へ戻す。
3. 「走ってみる」で道路・壁・車の位置関係が自然に動くかを確認する。「i」のFPS・p95を見て、画質と滑らかさの両立を評価する。
4. 画質が十分かを確認してから、通常ゲームの操舵・AI・全体展開へ進む。今回の試作で映像目標に届いたとは、ユーザー確認前に断定しない。
