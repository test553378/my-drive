# iPad Safariの意図しない画面拡大への対応（8.0.2）

## 調査結果と確定範囲

対象はiPad第9世代のSafari。実機がないため、報告された拡大を再現できておらず、Safariのページ拡大・ピンチ・ゲーム内カメラのどれが実機の原因だったかは未確定。

既存コードで確認できた不足は次のとおり。

- viewportは拡大を許可しており、これは説明・診断の可読性のため維持する。
- canvasや左右ボタンには既存の `touch-action: none` があったが、ゲーム全体を覆う有効期間付きの領域がなく、一部のHUD・ボタンには `manipulation` が設定されていた。
- `installGameGestures(document.body)` はcanvas・button等を判定した後の `dblclick` 抑制が中心だった。Safariがタッチ開始時に選ぶジェスチャーを、この遅いイベントだけで抑止できる証拠はなかった。
- 既存のタッチテストはCSS・合成Pointer Events・scale=1を確認していた。実機のダブルタップやピンチを再現したものではなかった。

以上はコード上の不足の確認であり、実機の根本原因を断定するものではない。画質、カメラ動作、道路、ミッションやレースの処理は変更しない。カメラには診断用のFOV読取値だけを追加する。

## 変更

- canvas・HUD・操作ボタン・余白・ミッション対象を `#play-surface` にまとめる。メニュー、読み込み、診断、エラー画面はこの領域の外に置く。
- レース・カウントダウン中だけ、領域とすべての子要素を `touch-action: none` にする。一時停止・結果・ガレージ・診断・読み込み時は解除する。body全体やviewportで拡大を禁止しない。
- Safariの `gesturestart/change/end` は、この有効領域でcancelableの場合に限り抑制する。
- 空白・HUDの近接した短い二度押しは、明示的な `passive: false` のtouchendでも補助的に抑制する。ボタン・リンク・フォーム等のtouchendは抑制せず、標準のclickを維持する。イベントからclickを合成しない。
- タッチの移動や複数指接触では二度押し履歴を破棄する。Touch Eventsはジェスチャー判定・診断だけを担当し、運転・消火入力は既存のPointer Eventsの所有権処理を使う。
- 回転、resize、visualViewport変更、blur、プレイ終了時に保持入力を解除する。既存のpointerup/cancel/lostpointercapture、visibility、pause処理と併用する。消火進捗は消さない。
- ページ全体の文字選択禁止をゲーム領域内に限定し、診断レポートの選択・コピーや説明画面のpan/pinchを維持する。
- 配布バージョンとService Workerキャッシュを更新し、旧HTML・bundle・CSSの組み合わせが残りにくいようにする。Actionsやリポジトリ設定は変更しない。
- 同じ入力モジュールを使う旧画質テストサイトも、新しい有効状態APIに合わせる。走行時のcanvasと操作領域に限定し、車の鑑賞操作と診断ダイアログを維持する。

## 端末内診断

「？」→動作診断→コピー／保存で明示的に取り出せる。自動送信・追加通信・永続的な入力ログ保存はしない。

- `viewport`：layout寸法、visualViewport寸法・scale・offset、devicePixelRatio。ゲーム起動失敗時にも取得する。
- `runtime.inputGestures`：制御の有効状態、現在のviewport、プレイ中のscale変化の観測有無、直近最大32イベント。イベント種別・対象のid/tag・接触本数・cancelable・抑制結果・単調時刻・scaleを記録する。入力文字列、接触座標、個人情報は記録しない。
- `runtime.cameraFov` と既存の `bufferSize` / `workCamera`：ゲーム内カメラとページの変化を区別する補助情報。FOVは通常の走行・ミッションでも変化し得る。

`viewport-scale-change` がプレイ中に出れば、ページのvisualViewportのscaleが変化した証拠になる。scaleが一定でもSafariの「ページの拡大」設定やiPadOSの拡大機能まで否定はできない。機種・iPadOS・Safariの設定と、HUDや操作ボタンも一緒に拡大したかを実機で確認する。診断を開いた後の操作は `active: false` として区別する。

## 自動テスト

- `tests/gestures.test.js`：領域と状態の限定、短い二度押しと長押しの区別、複数指・キャンセル、passive/cancelable、入力解除と消火進捗保持、診断上限・scale変化・リスナー破棄。
- `tests/gestures.spec.js`：実際のHTML/CSS上で横・縦、HUD・余白のヒットテスト、実タップの標準click、説明・診断のスクロール／文字選択、複数指・消火UI・解除を確認する。ゲームbundleだけをテスト用の軽量入力ハーネスへ置き換える。実際の入力・ミッションUIモジュールを使用するが、3D描画・実走行はこのテストでは確認しない。ChromiumではCDPの複数接触も実行する。
- `tests/touch.spec.js`：製品bundleと3D描画を使い、実レース中の適用、入力所有権、回転相当の中断、一時停止・再開・診断への切り替えを確認する。
- 既存の消火ミッションの実走行テスト、レース等の単体テスト、ビルド整合性・構文・整形チェックを併用する。

結果はPRと作業報告に記載する。LinuxのPlaywright WebKitはiPad実機のSafariではない。dblclick、合成イベント、CDPやscale=1の成功は、実機の拡大防止が確認できたことを意味しない。

## iPad実機での受け入れ確認（すべて未検証）

オンラインで更新後、診断が8.0.2であることを確認する。本タスクではmainへマージ・公開しないため、この確認はレビュー・配布後に実施する。

| 項目             | 操作と合格条件                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| 連続タップ       | 横向き・縦向きで、車両・HUD・ボタン間の余白を速く2回〜数回タップしてもページが拡大しない         |
| ボタン           | 左右を連打して各方向へ正しく動き、左右＋ブレーキの複数指操作を維持できる                         |
| ピンチ           | プレイ中の複数指接触・ピンチでページが拡大せず、指を離すと入力が解除される                       |
| ミッション       | 炎を長押しして進み、離す・キャンセルする・別の炎へ移すと保持が解除され、完了前の進捗が保存される |
| 中断             | 保持中の回転・一時停止・アプリ切り替え後に押しっぱなしが残らず、再開後に操作できる               |
| 説明と診断       | スクロール・ピンチ・必要な文字選択ができ、閉じて再開すればプレイ用制御が戻る                     |
| 配布とキャッシュ | 通常Safari／ホーム画面から更新後に8.0.2が読み込まれ、古いHTMLと新しいbundleが混在しない          |

問題が残る場合は拡大前後の診断を端末内へ保存し、ページのscale・寸法とカメラ情報を比較して次の修正を判断する。
