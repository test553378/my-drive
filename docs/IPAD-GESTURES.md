# iPad Safariの画面拡大対策（8.0.3）

## 今回確認した発生条件と前回の不足

ユーザーのiPad第9世代・Safari・Ver.8.0.2で、ホームのボタンがない部分のダブルタップと、レース中のターボ等のボタンのダブルタップで画面が拡大することが報告された。ゲームのどの画面でもピンチは不要という追加要件を適用した。

コードから確認した前回の不足：

- 対策の有効条件がレース／カウントダウンだけで、ホーム・車両選択・一時停止・結果画面は対象外だった。
- ホームは透明な別レイヤーで、余白の接触はメニューだけでなく下のcanvasにも届く構造だった。メニュー要素だけにリスナーを追加しても対象漏れが残る。
- レース中もtouchstart／touchmoveはpassiveで、ブラウザの拡大操作をタッチ開始時には止めていなかった。touchendの補助抑制もボタンを除外し、短い二度押しの非操作領域だけを対象としていた。
- CSSやdblclick、合成イベントの検証では、実機のネイティブな拡大防止を証明できていなかった。

ホームの対象漏れとボタンの抑制不足は確認済み。実機Safariの内部的なジェスチャー判定・イベント順序はこの環境では再現できておらず、OSやSafariの不具合だとは断定しない。カメラ、FOV制御、画質、車両、道路、ミッション、レース進行は変更しない。

## 8.0.3の対策

- レースではcanvas・HUD・ボタン・余白を含む既存のplay-surfaceを対象にする。touch-action:noneに加え、captureかつ明示的passive:falseのtouchstartで、cancelableなブラウザ既定動作を抑制する。touchmoveとSafariのgestureイベントも対象内だけ抑制する。
- ホーム・車両選択・一時停止・結果・ホームの読み込み中は、メニューと下のcanvasの共通祖先で接触を監視する。対象をplay-surface、modal、asset-loadingに限定し、診断・エラーのダイアログを含めない。
- メニューはtouch-action:pan-y。1本指の開始・移動とスクロール後の解放を妨げず、2本以上の接触とSafariのgestureイベントを抑制する。短いタップのtouchendも抑制し、二度押しによる拡大を防ぐ。
- ボタンも含めて短いタップを消費するため、既存のclick処理は同じボタン内でのタッチPointer Eventsの解放から1回だけ実行する。続いてブラウザが互換clickを発生させても重複実行しない。直前のボタンを閉じた後の互換clickも防ぐ。マウスとキーボードのclickは維持する。
- 左右・ブレーキ・ターボ・炎はdata-pointer-controlで区別し、既存のpointerdown／up／cancelの処理を継続する。ターボは押した瞬間、炎は長押しで動き、clickへ変換しない。患者・逃走車のタッチ処理も既存のclickハンドラーを使用する。
- 指が大きく動いた、ボタン外で離れた、cancel・lostpointercapture・回転・resize・中断があった場合はタップとして起動しない。保持入力は解除し、消火進捗は維持する。
- 診断を開いた時点でゲーム側の制御を解除し、閉じた時点で必要な制御を戻す。再描画フレームを待つ隙間を作らない。
- viewportによる一律の拡大禁止を追加しない。説明・診断のスクロールやコピー・文字選択を維持する。ゲーム画面のピンチは禁止するが、ゲーム操作領域外の診断閲覧は別に扱う。
- 配布バージョンを8.0.3、キャッシュをbokuno-grand-race-v8-20261123aへ更新。共有入力APIを使用する旧画質サイトのbundleも再生成する。新しい外部素材・依存ライブラリは追加しない。

## 端末内診断

「？」からコピー／保存できる。自動送信・追加通信・永続入力ログ保存はしない。

- viewport：layoutとvisualViewportの寸法、scale、offset、devicePixelRatio。
- runtime.inputGestures：レース側の有効状態と直近最大32イベント。
- runtime.menuGestures：ホーム側の有効状態と直近最大32イベント。pinchZoomAllowedはfalse。
- touchstart／touchend等のcancelableとprevented、pointer-tap、compatibility-click-blockedを記録。接触座標や入力文字列は保存しない。
- viewport-scale-changeとzoomObservedDuringPlayは、対応する領域が有効な間に観測したscale変化を示す。メニューもゲーム領域として監視する。
- 既存のcameraFov・bufferSizeも併用し、ブラウザの画面拡大とゲーム内カメラの変化を区別する。

scaleが変わればvisualViewportが変化した証拠になる。scaleが一定でもSafariのページ設定やOSの拡大機能まで否定はできない。診断の有効状態、バージョンと発生箇所を合わせて確認する。

## 自動検証の範囲

- 単体：有効範囲・passive/cancelable、ホームの1本指スクロールと複数指抑制、短いタップと長押しの区別、ボタンの1回起動と互換click抑止、キャンセル・中断、診断の上限を検証。
- 軽量ハーネス：実際のHTML/CSS・入力・ミッションUIモジュールを使う。横・縦のホーム余白をヒットテストして実タップし、ボタンの連打、画面切り替え、診断の解除・復帰を検証する。ハーネスは3Dを描画せず、実走行の代わりにはしない。
- ChromiumのCDP：ブラウザが生成する複数指・炎の保持／解放・メニューの1本指スワイプ・ピンチを検証。スクロールはハーネスで領域を小さくしてoverflowを発生させる。モバイルWebKitのPlaywrightはtouch-dragを提供しないため、そのスワイプはDOMのスクロールと非抑制イベントで確認する。
- 実ゲーム：有効なターボと、1回目の後に無効化されたターボへの2回目の実接触、音ボタン、複数指、停止・再開・回転を検証。
- 既存回帰：車両プレビューの回転、3車種のミッション、診断、更新・キャッシュのチェックを併用する。患者・逃走車はタッチ操作で確認する。

実行結果はPRと作業報告に記載する。LinuxのPlaywright WebKit、合成イベントやCDPの成功だけで、iPad実機のネイティブなダブルタップ／ピンチ防止を確認済みとは扱わない。

## iPad実機での受け入れ確認（未検証）

| 場所・操作               | 確認内容                                                                 |
| ------------------------ | ------------------------------------------------------------------------ |
| ホーム、車両・パーツ選択 | 余白や車両プレビュー、選択ボタンを速く何度タップしてもページが拡大しない |
