## 1. 目的・完成条件

消防車・救急車・パトカーに「緊急出動ミッション」を実装する。従来の2周レース中、各周1回（合計2回）発生するミッションは必須。**2回の達成と正規の2周完走**で、順位に関係なく「ヒーロークリア」とする。ライバル車両は通常どおり周回し、プレイヤーが消火・救護・追跡・停車・演出を行っている間もレース時間とライバルの走行は継続する。ライバル全車が先にゴールしてもプレイヤーの出動は終了しない。

消防車は火災現場に出動して放水、救急車は病人を救助して病院へ搬送、パトカーは逃走車を追跡してサイレンで停止させ、警察官が確認する。全4コース（C01初級、C02山道、C03シティ、C04グランプリ）で実装する。

**既存機能を保全**：8車種・4コース・3段階AI難易度、車両とパーツ選択、2周レース、ターボ、パンク・自動修理、横断歩道・歩行者ペナルティ、グラフィックス、画質設定、診断、音、オフライン対応、GitHub Pages。対象外の車種にミッションを追加しない。広告・課金・データ収集・外部CDNや外部APIを追加しない。

## 3. 委任された未決事項の推奨仕様

以下の数値・細部は**ユーザーの指定ではなく、設計上の推奨初期値**。質問①〜㊻と衝突しない範囲で実装時に調整できる。

### 3.1 出動候補とタイミング

- 各コース×各対象車種に**最低3件の有効候補**（合計36候補以上）を用意する。建物や病院などの素材は再利用可能。同一レースの1周目と2周目は別の候補から選ぶ。
- ランダム抽選は**シード付き**で再現可能にする。1周目に1件、2周目に1件、合計必ず2件。再挑戦時に重複抽選しない。
- 各周の途中でランダムに指令を出すが、進入すべき分岐の十分手前で通知。案内距離は現在速度・制動距離・曲率を考慮し、**通知した瞬間に分岐を通り過ぎている事態を禁止**する。
- 1周目のミッションが未達成の間は2周目の指令を出さない。

### 3.2 実際に走れる道路とUターン

- **見た目だけの脇道は禁止**。各コースに実走可能な分岐、脇道、現場、病院、環状追跡道路、本線への合流を作り、走行の衝突判定・車体の向き・経路案内と連動させる。
- 道路を本線・分岐・環状ルート・合流の「道路グラフ」として管理し、車両を現在エッジ・ワールド位置・向き・進行方向で表現する。既存の左右操作により実際に分岐を曲がれること。
- Uターンボタンは**車体の向きと実際の前進方向をともに180度変更**する。車の絵だけ回転させて、本線上の進行距離を増やし続ける実装は不可。連打抑止と安全な回転余地を確保する。
- Uターン可能期間は出動指令〜本線復帰完了のみ。通常レースや対象外車種では使えない。作業中は運転ボタンと一緒に非表示。
- 行き止まり・崖・トンネル・既存建造物・ガードレールに道路が衝突しないようコース固有の道路配置を用意。誤った方向へ進んでも物理的に現場・本線へ帰れる構造にする。
- 停車エリアに入ると安全に減速して自動停止。作業後は**自動発進**するが、本線まで自動運転・自動テレポートは行わず、子ども自身が運転する。ミニマップと大きな矢印は、逆走・目的地変更にも追従する。

### 3.3 周回・順位・終了判定（最優先の実装上の注意）

- 既存Ver.7の `s.z` は単調増加する本線進行距離であり、そのままでは脇道とUターンを扱えない。**プレイヤーの物理位置・道路経路と、本線のレース進捗・周回判定を分離**する。
- 本線の正方向チェックポイントの順序、ラインの正方向通過、当該周ミッション完了の3条件を組み合わせて周回成立。未達成でラインを越えても**通過を保留・遡及加算しない**。達成後に自力で再度正方向からラインを越える必要がある。
- 逆走時やラインの往復、分岐ショートカット、ライン付近の連打で周回加算しない。Uターンで戻った後でも適切にチェックポイント状態を管理し、正規ルートで完走できる。
- 脇道走行中の距離は順位に加算しない。順位は本線で最後に確定した正規レース進捗を基本に表示。ライバルは既存の本線レースAIで走り、2周で先にゴールしたらその順位を確定する。全車ゴール後もプレイヤーはミッション継続できる。
- **ヒーロークリアは「2件ミッション達成済み AND 正規2周完走」**のみ。未達成のまま走行距離が2周分を超えてもレースは終了しない。結果画面には順位とヒーロークリアを併記する。

## 4. 車種別ミッション（必須）

### 4.1 消防車：消火

`出動指令 → 脇道へ運転 → 指定エリアで自動停止 → 作業用3Dカメラ → 2〜3か所の火を全部消す → 成功 → サイレンOFF → 通常視点・運転ボタン復帰 → 自動発進 → 自分で本線へ戻る`

- 炎は建物の窓・屋根など、**同じ画面に2〜3か所同時表示**。自由な順で消せる。放水中、カメラは動かない。
- 火を長押しした間だけ水が出る。累積約2〜3秒の放水でその炎が徐々に縮小して消える（初期目安2.5秒）。途中で指を離したら放水のみ停止、火の縮小状態と消火進捗は保持する。再長押しで続きから消火。
- タッチ対象は3Dの炎に対応した十分大きい当たり判定を用意。1本のホースの操作対象は同時に1か所。複数指・`pointercancel`・画面切替時の入力残りを防ぐ。
- 全炎を消すまで成功させない。怖い事故や負傷を描かず、消火成功を明確な3D水しぶき・音・短いお祝いで示す。

### 4.2 救急車：救助と搬送

`出動指令 → 病人のいる現場へ運転 → 自動停止 → 作業用3Dカメラ → 病人を1回タッチ → 隊員が降りて付き添い乗車 → 通常視点へ戻り自動発進 → 指定病院へ自分で運転 → 自動停止 → 隊員が自動で病人を院内へ運ぶ → 成功・サイレンOFF → 自動発進 → 自分で本線復帰`

- 1回のミッションで救助する病人は**1人**、レース全体で2人。
- 各コースに最低**2つの見分けやすい病院**を置き、1件ごとに到達可能な病院をランダム指定。病院の外観・案内看板は子どもが区別できるようにする。
- 病人へのタッチは1回。救急隊員の降車、付き添い、乗車は3Dアニメーションで自動実行。病院到着後の降車・院内への搬送も自動。病院で追加操作を要求しない。
- **病人を救急車に乗せた時点では成功にしない。病院での引き渡し完了が成功条件。**
- 搬送時間制限なし。道を間違えてもUターンして目的地へ向かえる。矢印・ミニマップの目的地は「病人→病院→本線」と更新する。病状悪化や怖い医療描写を加えない。

### 4.3 パトカー：逃走車の追跡と確認

`出動指令 → 手動でサイレンON → 本線から脇道へ → 環状ルートで逃走車を自力追跡 → 接近かつサイレンON → 逃走車・パトカーが安全停止 → 停止した逃走車をタッチ → 警察官が降車し運転手を確認 → 成功・サイレンOFF → 自動発進 → 自分で本線復帰`

- 逃走車は通常のライバルレース車両とは**別の個体**で、捕獲されるまで脇道の**閉じた環状ルート**を周回。距離による速度補正・待機・ワープ・追跡のリセットは禁止。
- 逃走車の巡航速度はプレイヤーの**通常走行速度の70〜80％**（初期目安75％）。曲率などに対する安全な速度制御は可。プレイヤーの接近・離脱をトリガーにした速度調整は不可。
- 捕獲条件はワールド座標上の十分近い距離（初期目安約10m以内、同じ走行経路上）**かつサイレンON**。サイレンを先に鳴らしていても、接近後にONにしても捕獲できる。サウンドをミュートしていてもゲーム内部のON/OFF状態で判定する。
- 逃走車停止直後は**ミッション未達成**。パトカーも自動停止し、拡大表示された逃走車をプレイヤーがタッチすると、警察官が降りて運転手を確認。演出終了で初めて成功。停止車両の二重タップでアニメーションを二重起動しない。
- 警察官が安全に声をかける穏やかな表現とし、暴力、負傷、恐ろしい取り調べの描写は不要。

## 5. UI・音声・カメラと運転制御

- 出動指令では無線の短い呼び出し音＋日本語音声＋ひらがなテキスト＋イラストを表示。例：「かじだ！ げんばへ むかおう」「ひとを たすけよう」「にげる くるまを おいかけよう」。音声は子どもに分かりやすい短さ・音量とし、端末で音声を使えない場合も画面案内で遊べること。
- 画面には「おしごと 0/2、1/2、2/2」を大きく表示。ミニマップでは本線・脇道・現在地と向き・分岐・目的地・帰路を表示。大きい矢印は進行方向を誤解しないよう道路グラフの経路に基づいて更新する。
- 作業場所の指定エリアに入ると自動減速・停止。車体停止後にカメラを3Dクローズアップへ自動切替。消防は2〜3火のすべてを同じ画面に収めて**カメラ固定**、救急は病人と隊員、警察は逃走車と警察官の確認を大きく表示。2D画像で代用せずゲームの3D世界と連続させる。
- **作業中は左右・ブレーキ・ターボ・Uターンなどの運転ボタンを非表示かつ入力無効にする。** 作業終了で運転ボタンと通常カメラを復元、自動発進。押しっぱなし入力は作業開始時に解除する。停止を解除するための「しゅっぱつ」ボタンは不要。
- Uターンは指令〜本線復帰完了まで表示、作業中は隠す。180度回転のアニメーションを短く行い、操作の二重発火を防ぐ。画面のセーフエリア・子どもの指での長押し・連続タップ・複数指・ダブルタップ拡大抑止に対応する。
- サイレンは消防・救急が指令と同時に自動ON、警察が指令時OFFで手動ON。**3車種とも手動でON/OFF可能**。ミッション成功時に3車種とも自動OFF。次の指令時は再度、車種ごとの初期ルールで開始する。
- サイレンONの状態は実際の音声出力と分離する（端末がミュートでもパトカーは捕獲可能）。ブラウザーの音声制限を考慮し、再生できなければ視覚的な案内が残る。外部の有料音声APIや個人情報送信を要件にしない。
- 既存のポーズ、背景化時の停止、明示的再開、WebGL復旧時の保護は維持する。意図的なポーズ中以外は、作業中でもライバルのAI・時計が進む。

## 6. 状態管理・安全性

- 共通状態遷移：`RACE → DISPATCH → DRIVE_TO_SCENE → AUTO_STOP → ACTION → SUCCESS → RETURN_TO_TRACK → RACE`。
- 救急車は `ACTION → PATIENT_ONBOARD → DRIVE_TO_HOSPITAL → HOSPITAL_STOP → HANDOFF → SUCCESS`、パトカーは `DRIVE_TO_SCENE → CHASE_LOOP → SUSPECT_STOPPED → POLICE_CHECK → SUCCESS` を明示して管理する。炎の残量・救急車の患者搭乗状態・逃走車位置・ミッション達成数は単一の状態機械で管理し、二重計上しない。
- 作業中もVer.7の歩行者安全ルールとペナルティを保持。ただし画面が作業用カメラになり車が自動停止した状態では新たな誤操作による衝突を発生させない。Ver.7の現行値は歩行者接触時**3秒停止＋10秒ペナルティ**（`race-config.js`）。
- ミッション未達成でゴール・ライバル先着・画面切替などが起きてもミッションが消えない。一時停止では消火残量・乗車状態等を保持。リロードをまたぐセーブは今回の必須対象外（推奨）。
- 火災の怖い負傷描写、病人の苦痛表現、暴力的な捕獲を加えない。外部広告・アカウント・個人情報収集を追加しない。

## 7. 既存コードに関する実装上の注意

2026年11月13日に対象のGitHubリポジトリを確認した。現行Ver.7は本線の走行距離`s.z`が単調増加し、`tracks.js` の `trackPose()` で車両位置を計算、`driving.js` の `progress()` とチェックポイントが周回・ゴール判定を担う。**このままでは任意の脇道・逆走・Uターン・正方向ライン再通過の判定が成立しない。** 路面形状だけを増やす不完全実装を禁止する。

推奨する責務分離：

| モジュール | 実装責務 |
|---|---|
| `tracks.js`＋新規道路グラフ | 全4コースの実走可能な分岐・脇道・環状追跡路・合流・現場・病院の経路データ |
| `driving.js` | 実際の進行方向・Uターン・分岐の選択・自動停車・正方向チェックポイント判定・周回ゲート |
| 新規`missions.js`など | ミッション候補抽選、状態遷移、炎の進捗、救急搬送、逃走車の追跡と捕獲 |
| `game-main.js`、`input.js`、`index.html`、`style.css` | ミッションHUD、無線音声、タッチ入力、Uターン、操作の非表示、案内更新 |
| `render/` | 実3D道路・建物・病院・炎・水・人物演出・クローズアップカメラ |
| `race-metrics.js`、`rival-ai.js` | 脇道距離を順位に含めないこと、ライバル先着後のプレイヤー続行、従来AI保全 |
| サービスワーカー・ビルド処理 | 新素材の自己配信・キャッシュ・ライセンス記載・生成物整合性 |

Three.js/WebGL2の画質構成を維持する。重いアセットを無計画に増やさず、同一素材の再利用、LOD、表示範囲制御、メモリ解放でiPadに配慮する。**iPad第9世代での実機FPS・発熱・長時間動作は現行READMEでも未検証**なので、検証していないものを「確認済み」と報告しない。実機30fpsを努力目標（推奨）とし、重ければ既存の軽量画質に切り替えられるようにする。
