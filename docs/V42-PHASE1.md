# Ver.4.2 Phase 1 — 現状調査（2026-11-09）

調査対象は公開版Ver.6、コミット `e974664`。要件書のVer.4.2は仕様名として扱います。今回は指示どおりPhase 1・2を先行し、映像をユーザーが確認してからPhase 3以降へ進みます。

## 現在の実装

| 項目 | 現状・根拠 |
|---|---|
| エンジン | `game.js` の独自WebGL 1。頂点色・法線・材質番号のバッファを自作。外部モデルローダー／UV付きPBRテクスチャ／HDR環境マップは未導入 |
| 車体 | `vehicles.js` の手続き生成。曲面・ガラス・ホイールはあるが、反射は関数で生成した擬似環境、接地影は平面メッシュ。シャドウマッピングはない |
| コース | `tracks.js` の距離パラメーター付き閉曲線。4コースの高さ・接線・曲率・幅を共通形式で扱う。`world.js` が道路／景観を生成。路面の模様はシェーダーのノイズで、実写素材ではない |
| 操作 | `driving.js` に `offset *= exp(-dt * .85...)` の中央復帰あり。操舵速度にも減衰残りがある。難コースの曲率ドリフトもあるため、FR-07の位置維持は未実装。Phase 3で通常走行と修理等の例外を分けて改修する |
| AI | プレイヤー車の最高速度の82〜87%を基準に、曲率で速度倍率を変える簡易AI。障害物回避の横位置変更は瞬時。加速／先読み制動／滑らかな追越し／3難易度は未実装。歩行者に停止するが、AI個体ごとのパンク・修理・接触加算はなく、FR-08の公平性には追加実装が必要 |
| 既存機能 | 8台・7カテゴリー、4コース、パーツ・塗装選択、プレイヤーのパンク・修理、横断歩行者・10秒加算と3秒停止、ブレーキ、ターボ、緊急車サイレン、2周・順位・タイム、タッチ／拡大防止、Pages・診断・復旧は実装済み |

## 描画方式の比較

| 方式 | 利点 | 今回の課題 |
|---|---|---|
| 独自WebGLを拡張 | 現行互換性・小さな配信量。WebGL 1で動く | GLB階層・PBR・HDR前処理・影・アセット破棄を新規実装する必要があり、画質と保守性の改善に時間がかかる |
| Three.js / WebGLRenderer | GLTFLoader・PBR・環境マップ・トーンマッピング・影・各リソースの破棄が利用できる。車輪等の階層も保持できる | 配信量・シェーダー負荷が増える。現行Three.jsはWebGL 2が必要。実機のFPSとメモリ評価が必要 |

Phase 2はThree.jsの別ページ `graphics-lab/` を採用します。既存ゲームのエンジンはこの段階では置き換えません。既存C01の距離・曲線データを利用した走行と、外部GLBスポーツカー1台で評価します。単なる背景画像の置換ではなく、車・路面・縁石・壁等は3Dとして描画します。HDRIは遠景と反射・照明に使います。

## 素材の検討と性能の検証方針

- 車：Khronos glTF Sample AssetsのCar Conceptを候補とする。Unity FanのCC0原型をEric Chadwick / Darmstadt Graphics Groupが最適化したCC-BY-4.0モデル。実在メーカーの車両ではない。付属のKhronos等のロゴはCCライセンスの対象外のため、ロゴ用部品・画像を除去した派生GLBを作り、変更を明記する。
- 路面：Poly HavenのAsphalt Track（Dimitrios Savva、CC0）。実写由来の色・法線・粗さを使用する。
- 環境：Poly HavenのHDRIを候補とし、反射と遠景を使い分ける。権利・作者・サイズは採用時に記録する。
- 自己ホストの固定版エンジンと素材を相対パスで配信する。素材の実行時CDN読み込み・追跡・購入は行わない。
- 20MB以下の初回配信量を目標とする。画質3段階、解像度上限、単一の影光源、メッシュ集約・描画範囲制限を設ける。転送量と描画負荷を測り、実機FPSは未検証と明記する。
- ロード進捗、読込対象と原因を出すエラー、WebGL生成／喪失・復旧診断、端末内だけの統計を用意する。正常に表示できない際に低品質な代用品へ黙って置き換えない。

## Phase 1 の検証

実行コードを読み、描画方式・車両／コース構造・中央復帰の具体式・AIの速度／回避処理を確認しました。まだ画質・iPad性能の改善を達成したとは判定していません。画質の評価用ページと比較画像はPhase 2で作成します。
