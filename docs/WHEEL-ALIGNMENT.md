# 画質確認ページ：前輪の初期角度修正

対象は `graphics-lab/` の1車両・1コース試作。修正版の診断バージョンは `graphics-p2.2`。本ゲームの仕様・操縦補助・AI、Actions設定、リポジトリ設定は変更しない。

## 原因と修正

配布中の `concept-high.glb` と `concept-mobile.glb` を読み、車輪ノードの親階層を含む座標変換を調べた。両モデルとも、左右の前輪の車軸は車体座標で約 `[0.8660254, 0, 0.5]`、後輪は `[1, 0, 0]`。前輪が約−30度操舵したポーズで保存されている。

旧処理は子部品のワールド変換を保って操舵・回転用のグループに取り付けていた。このため操舵グループの角度を0にしても、部品側の初期角度が残った。また、車体のX軸で転がす処理と前輪の実際の車軸が一致していなかった。従来のブラウザテストはグループ角度のみ確認し、部品の車軸の向きは確認していなかった。

`graphics-lab/src/wheel-rig.js` に取り付け処理を分離。モデルの車軸から初期ヨー角を求め、車輪中心を支点として、タイヤ・リム・ディスク・キャリパーに補正する。30度を固定値として指定せず、元の部品の回転位相・左右・スケール・車軸中心を保持する。転がる部品とキャリパーは従来どおり別グループに置く。これにより、静止・直進時は前輪をまっすぐにし、操作中は操作分だけ操舵し、回転中も車軸がぶれない構造にする。

GLB・画像の差し替え、外部素材・依存ライブラリの追加はない。既存のクレジットとライセンス文書を維持する。配信用バンドルとそのハッシュを再生成する。

## 検証

- 高画質・モバイルの実際のGLBから階層と変換を読み込む回帰テストを追加。旧処理で両方失敗し、補正後は両方通過することを確認した。
- 全4輪について、静止・直進・左右操舵・操舵解除と複数の回転位相で、リムの車軸が期待方向を向くことを確認。車軸中心が動かず、キャリパーがタイヤと一緒に回転しないことも検証する。
- `npm run build:graphics`、`npm run check`、`npm test`（42件）成功。
- Chromium／Linux WebKitによる画質試作のブラウザテスト：計16件すべて成功（各8件）。描画ピクセル、縦横表示、実際の走行操作、画質切替、GPU資源解放、読み込み失敗、連続GPU喪失・復旧、シェーダー診断を検証した。
- Linux WebKitの標準画質で、同じ視点の修正前後の描画画像を保存・確認した。新しい画像素材としてリポジトリには追加していない。

画面比較はLinux上のブラウザによるもので、iPad第9世代の実機検証ではない。公開後にはiPad Safariで標準・高画質の正面／側面を確認し、直進・左右操作・解除後の前輪の向きと回転を確認する必要がある。FPS・発熱等の実機項目も引き続き未検証。
